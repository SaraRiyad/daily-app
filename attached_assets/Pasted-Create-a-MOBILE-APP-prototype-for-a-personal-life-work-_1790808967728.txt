App Concept

The app helps the user organize their everyday life, work, working hours, salary, income, and expenses in one place.

The main areas are:

Home
Tasks
Work
Money
Calendar
1. Home

Create a personalized home screen that gives the user a quick overview of their day.

Show:

Greeting
Today's date
Today's tasks
Current work status
Clock In / Clock Out action
Today's working hours
Today's estimated salary
Current balance

The most important information should be visible without making the screen feel crowded.

Example:

"Good morning 👋"

Today's Tasks
2 of 5 completed

Work
Not clocked in

[ Clock In ]

Today's earnings
$42

Balance
$350

Use the reference design's card and component style.

2. Tasks

Create a mobile-friendly task management screen.

The user can:

Add a task
Edit a task
Delete a task
Mark a task as completed
Set a due date
Set priority

Organize tasks into:

Today
Upcoming
Completed

Each task should be visually simple and easy to check off.

Include a clear "+" button or equivalent action for adding a task.

3. Work

Create a Work section where the user can manage multiple jobs.

The user can have more than one job.

For example:

Job 1:
"Coffee Shop"

Normal rate: $5/hour
Overtime rate: $7/hour

Job 2:
"Freelance"

Normal rate: $8/hour
Overtime rate: $10/hour

Allow the user to select which job they are currently working at.

Each job should have its own:

Hourly rates
Work history
Working hours
Salary calculations
Days worked
Days off

11. Prototype Behavior

This should feel like a real interactive mobile app prototype.

For example:

Home → Clock In → Working State → Clock Out → Work Summary

Home → Tasks → Add Task → Task appears in Today's Tasks

Work → Select Job → Job Details → Work History

Money → Income → Add Income → Income appears in list

Money → Expenses → Add Expense → Expense appears in list

Calendar → Select Day → Mark as Day Off

Use realistic sample data so the screens don't look empty.

12. Design Rules

The reference prototype is the source of truth for the visual design.

Prioritize consistency over adding visual effects.

DO:

Reuse the reference colors
Reuse the reference typography style
Reuse the reference component style
Reuse its spacing and visual hierarchy
Keep the interface clean
Keep it mobile-first
Make important actions easy to find

DO NOT:

Create a completely new theme
Use random colors
Make it look like an enterprise HR dashboard
Add unnecessary features
Turn it into a desktop dashboard
Overcrowd the screens

The final result should look like a natural extension of the reference prototype, but for a personal life/work/money management application.

Focus primarily on polished UI/UX and a convincing mobile prototype rather than backend complexity.
